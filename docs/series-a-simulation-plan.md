# シリーズA「シミュレーション検証」構成案

作成日: 2026-08-08

> 注記: 以下のランキングは実測の再生数データベースではなく、**既存の人気シミュレーション動画の題材分布・検索需要・題材の性質**から筆者（Claude）が組み立てた評価です。数値スコアは相対的な目安。

---

## 0. なぜ「100万回」が効くのか

この型が伸びる理由は3つに分解できる。**題材選定はこの3条件を満たすかで決める。**

1. **直感と結果がズレる** — 「え、そうなるの？」がサムネとタイトルの燃料。ズレがない題材は伸びない
2. **試行回数が意味を持つ** — 1回では分からないが100万回で法則が浮かぶ。だから「100万回」に必然性がある
3. **プロセスが絵になる** — 点が動く・分布が形になる・グラフが伸びる。結果だけ数字で出す題材は8分もたない

**この3つ全部を満たす題材だけを採用する。** 2つしか満たさないものは Shorts に回す。

## 1. 何を試行させることが多いか（ジャンル別・人気順）

### Tier S — 確率パラドックス系（最頻出・最も再生される）

「数学的に正しいのに納得できない」型。**この分野が圧倒的に本数が多く、日本語圏でもゆっくり解説で繰り返し作られている＝需要が実証済み**。競合は多いが、可視化の質で殴れる。

| 題材 | 直感とのズレ | 可視化の映え | 実装コスト | 備考 |
|---|---|---|---|---|
| **モンティ・ホール問題** | ★★★★★ | ★★★☆☆ | 低 | この分野の定番中の定番。既に何十本もある＝需要の証明。ドア数を100枚に増やす演出で差別化 |
| **ギャンブラーの破産／マーチンゲール法** | ★★★★★ | ★★★★★ | 低 | 「必勝法」が破産する様を1万人分同時に走らせると絵が強烈。日本語圏で伸びやすい |
| **誕生日のパラドックス** | ★★★★☆ | ★★★☆☆ | 低 | 23人で50%。教室を実際に埋めていく可視化 |
| **ガチャ・天井の確率** | ★★★★☆ | ★★★★☆ | 低 | **日本圏特化で最強クラス**。1%ガチャを100連で当たらない確率、天井までの期待コスト |
| **くじ引きの順番は有利不利があるか** | ★★★★☆ | ★★★☆☆ | 低 | 「先に引く方が得」という広い誤解を叩ける |

### Tier A-1 — 社会・経済シミュレーション（伸び代が最も大きい）

**Tier S より競合が薄く、テーマの射程が広いので視聴者層が桁違いに広い。ここが本命。**

| 題材 | 内容 | 評価 |
|---|---|---|
| **全員同額スタートで金をランダム交換すると格差は生まれるか** | 100人が1万円ずつ持ち、ランダムに1円ずつ渡し合う。結果は必ず指数分布に収束＝**実力も運の偏りもなくても格差は生まれる** | ★★★★★ この型の最高傑作級。分布が育つ様子がそのまま8分の絵になる |
| **囚人のジレンマ大会（Axelrod トーナメント）** | しっぺ返し戦略が優勝する。Veritasium の大ヒット回の題材 | ★★★★★ 戦略を自作追加できるのでシリーズ化しやすい |
| **シェリングの分居モデル** | 「隣人の3割が同類ならOK」という穏やかな選好だけで、街は完全に分断される | ★★★★★ 社会的射程が広く、絵が非常に強い |
| **信頼の進化 / 裏切り者の混入率** | 正直者と詐欺師の割合をどこまで許容できるか | ★★★★☆ |
| **ランダムに選んだリーダー vs 実力で選んだリーダー** | ピーターの法則。無能の水準まで昇進する | ★★★★☆ 職場ネタで刺さる |

### Tier A-2 — 進化・生態系シミュレーション

Primer が確立した型。**視覚的完成度が要求されるが、当たると最も長く再生され続ける**（エバーグリーン性が最強）。

| 題材 | 評価 |
|---|---|
| **自然選択（サイズ・速度・感知範囲を持つ生物が餌を奪い合う）** | ★★★★★ Primer 最大のヒット題材。1本目に置く価値あり |
| **利他行動はなぜ生まれるか（血縁選択・緑ひげ効果）** | ★★★★☆ |
| **捕食者と被食者の個体数振動（ロトカ・ヴォルテラ）** | ★★★★☆ グラフと画面が同期して動くと美しい |
| **群れ（Boids）と捕食者** | ★★★★☆ 実装が軽く絵が最高。初回に向く |
| **ニューラルネットに歩行を学習させる** | ★★★☆☆ 実装コスト高だが「AIが勝手に変な歩き方を発明する」オチが強い |

### Tier B-1 — 交通・群衆・物理

| 題材 | 内容 | 評価 |
|---|---|---|
| **自然渋滞（ファントム渋滞）** | 誰もブレーキを踏んでいないのに渋滞が生まれる。1台の減速が後方に伝播 | ★★★★★ 日常題材で最も刺さる。**Tier A 相当** |

### Tier B-2 — 数学・計算

競合が強く、単体では弱い。**他 Tier の回の導入や検証パートに混ぜる素材として使う。**

- モンテカルロ法でπを求める（★★★☆☆／導入向き）

## 2. 総合ランキング（このチャンネルで作る順）

再生ポテンシャル × 実装コスト × 差別化余地で並べ直したもの。

| # | 題材 | 分類 | 理由 |
|---|---|---|---|
| 1 | **お金をランダムに交換すると格差は生まれるか** | A-1 | 絵・オチ・射程が全部最上位。実装は最も軽い |
| 2 | **自然渋滞はなぜ起きるか** | B-1 | 日常題材で検索需要が高く、可視化が直感的 |
| 3 | **マーチンゲール法は本当に負けないのか** | S | 1万人同時破産の絵が強烈。実装ほぼゼロ |
| 4 | **シェリングの分居モデル** | A-1 | 社会的射程が最大 |
| 5 | **自然選択シミュレーション** | A-2 | エバーグリーン性最強。ただし作り込み必須 |
| 6 | **囚人のジレンマ大会** | A-1 | 戦略追加で第2弾・第3弾が作れる |
| 7 | **ガチャ確率と天井** | S | 日本圏特化。数字が生々しい |
| 8 | **エスカレーター片側空け問題** | B-1 | 議論を呼ぶ＝コメントが伸びる |
| 9 | **Boids と捕食者** | A-2 | 実装が軽く映像が美しい。息抜き回に |
| 10 | **モンティ・ホール（ドア100枚版）** | S | 定番。演出で差別化 |
| 11 | **避難シミュレーションと柱の逆説** | B-1 | 反直感オチ |
| 12 | **レジの列は1列か各列か** | B-1 | 待ち行列。日常題材 |

**初回は #1 か #2 を強く推奨。** 実装が軽く、8分の構成が最も自然に立ち、かつオチが強い。

## 3. 1本8〜12分のテンプレート構成

全12本で同じ骨格を使う（構成の使い回しは問題なし。**結論が毎回違えば量産型判定にはかからない**）。

| 時間 | パート | 内容 |
|---|---|---|
| 0:00–0:45 | **フック** | 結果の一部を先に見せる。「このグラフ、全員同じ金額から始めています」 |
| 0:45–2:00 | **ルール提示** | シミュレーションのルールを画面上で1つずつ組み立てる。視聴者に予想させる |
| 2:00–4:00 | **第1回実行** | 少数（10〜100体）でゆっくり見せる。ここが可視化の見せ場 |
| 4:00–6:30 | **スケールアップ** | 100万回／1万体へ。分布・グラフが形になる瞬間 |
| 6:30–8:30 | **条件を変えて再実行 ×2** | 「では、こうしたら？」再分配を入れる／初期条件を変える。**尺はここで稼ぐ** |
| 8:30–9:30 | **考察と結論** | 自分の解釈と主張を必ず入れる（ポリシー上も重要） |
| 9:30–10:00 | **次回の問い** | シリーズ回遊 |

## 4. 共通シミュレーション基盤（1回作れば12本使い回せる）

```
sim/
  core/
    engine.js       # 固定タイムステップのループ、シード付き乱数(再現性)
    recorder.js     # requestAnimationFrame を使わずフレーム単位で進める
    render.js       # Canvas2D 描画プリミティブ（粒子・軌跡・ラベル）
    charts.js       # 分布ヒストグラム、時系列、ジニ係数などの指標グラフ
    theme.js        # 全動画共通の配色・タイポ
  episodes/
    01-wealth/      # 各回はルールとパラメータだけを書く
    02-traffic/
    ...
tools/
  capture.mjs       # Playwright で 1920x1080 のフレーム連番を出力
  encode.sh         # ffmpeg で結合
```

**設計上の要点:**

- **シード付き乱数を必ず使う** — 「あの結果をもう一度」が再現できないと編集で詰む
- **実時間で録画しない** — `engine.step()` を手動で回してフレームを1枚ずつ吐く。100万回の試行を実時間で見せる必要はなく、「1000回ごとに1フレーム」のように**時間を圧縮する演出**が本質
- **指標グラフを常時画面に置く** — 粒子だけ見せても8分もたない。ジニ係数・平均・分散が伸びるグラフを併走させることで「進んでいる感」が出る
- **カウンタを画面に出す** — 「試行回数 847,312」が回り続けるだけで滞在時間が伸びる
