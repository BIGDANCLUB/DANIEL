# Claude で作る 8分以上・16:9 YouTube シリーズ 候補案

作成日: 2026-08-08

## 0. 前提：2026年時点の「bot判定」の実体

「bot判定」と呼ばれているものは、実際には **2025年7月に改称された YouTube の「量産型コンテンツ（inauthentic content）」ポリシー** と、その自動検知による YPP 剥奪／収益化停止のこと。2026年に入って大量の AI チャンネルがこれで停止している。

落ちる基準（＝作ってはいけない型）:

- 他人が作った文章・ニュース・Wikipedia などを **そのまま読み上げる**だけ
- **テンプレートの差し替え量産**（タイトルと題材だけ変えた同一構成）
- **AI画像スライドショー＋合成音声**のみ、編集・構成・語りの付加価値なし
- 既存動画の内容を AI 音声・AI 画像で置換しただけ
- 解説なしの切り抜き・まとめ・ランキング

**逆に落ちない条件は明確**: 「情報そのもの」ではなく **制作者の実験・検証・主張・オリジナル制作物** が中心にあること。AI を使うこと自体は禁止されておらず、`合成コンテンツの開示`トグルを ON にしても収益化資格は失われない。

→ したがって **Claude の強みは「AI で映像を生成する」方向ではなく、「コードを書いて、実際に動くもの・実測結果を作り、それを画面として記録する」方向に使うのが最も安全かつ模倣可能**。生成物は 100% 自作物なので、量産型判定に原理的にかかりにくい。

## 1. 候補シリーズ

### 候補A: シミュレーション検証系 ★最推奨
> 「〇〇を100万回シミュレーションしたらどうなるか」

- **参考にできる既存チャンネル**: Primer、Sebastian Lague、Veritasium のシミュレーション回
- **題材例**: モンティホール／じゃんけん戦略の進化／交通渋滞の発生（自然渋滞の再現）／群衆避難／Boids と捕食者／感染シミュレーション／格差はなぜ生まれるか（初期条件同一の経済シム）／じゃんけん・囚人のジレンマ大会
- **8分の埋め方**: 問題提起(1分) → ルール説明とシム構築(2分) → 第1回実行と意外な結果(2分) → 条件を変えて再実行 ×2(2.5分) → 結論と次回の問い(0.5分)
- **Claude 担当範囲**: 企画・台本・シミュレータ実装(Canvas/JS or Python)・グラフ描画・録画スクリプト・サムネ SVG まで全部
- **ポリシー耐性**: ◎ 実験結果は世界に存在しないオリジナルデータ
- **難点**: 1本あたりの実装コストが中〜高。ただしシム基盤を使い回せる

### 候補B: アルゴリズム可視化・対決系
> 「ソートアルゴリズム、100万件で本気で殴り合わせてみた」

- **題材例**: ソート／経路探索(A*, Dijkstra, BFS)／迷路生成／圧縮アルゴリズム／乱数の質／レイトレーシングを1から／衝突判定の最適化
- **8分の埋め方**: 可視化(遅い動きをそのまま見せる)＋実測ベンチマーク＋「なぜ速いのか」の解説。可視化パートは自然に尺を食う
- **ポリシー耐性**: ◎（自作コード・自作ベンチ結果）
- **強み**: 視覚的に強く、サムネが作りやすい。海外は競合多いが**日本語圏は手薄**
- **難点**: 視聴者層がやや狭い（CPMは技術系で悪くない）

### 候補C: 自作ゲーム AI 対戦・観戦系 ★このリポジトリと直結
> 「自作の戦略ゲームで AI 同士を1000戦させたら、最強戦術が判明した」

- 既に `gyakuten.html` / ファーレントゥーガ風 SLG の資産がある。ここに AI プレイヤーを実装して総当たり・進化学習させ、その過程を実況する
- **8分の埋め方**: ルール紹介 → 手作り戦術 vs 総当たり → 勝率表 → 進化させた結果生まれた「人間が思いつかない戦術」 → 人間(あなた)が挑戦
- **ポリシー耐性**: ◎ ゲームもAIも自作、実測データ
- **強み**: 「作る」「戦わせる」「意外な結論」の三点が揃い、シリーズ化しやすい。ゲーム自体を公開すれば回遊も作れる
- **難点**: 初回の作り込みが重い。ただし2本目以降は激軽

### 候補D: データ可視化ドキュメンタリー
> Economics Explained / RealLifeLore 型。地理・経済・統計をアニメーションチャートで

- **題材例**: 日本の人口推計を1本のグラフで／各国の電力構成の変遷／東京の地価と通勤時間／為替と物価の実感差
- **必須条件**: 一次データ（e-Stat、World Bank、IMF、政府オープンデータの CSV/API）を自分で取得・加工し、**独自の切り口と結論**を付ける。記事の要約読み上げは即アウト
- **ポリシー耐性**: ○（データ加工と主張がオリジナルなら可。要約系に寄せると危険）
- **強み**: CPM が高い（金融・経済で RPM $10-15 帯）。長尺と相性が良い
- **難点**: 「AI雑学読み上げ」に最も近い型なので、演出と主張で差別化しないと巻き込み事故のリスク

### 候補E: 「作ってみた」制作ドキュメント
> 「ブラウザだけで〇〇を作る」プロセスをそのまま8分に

- **題材例**: 逆転裁判風ゲーム／物理エンジン自作／自作フォント／ローグライク／音声合成をゼロから
- **ポリシー耐性**: ◎ 最強クラス（制作過程は完全な一次コンテンツ）
- **強み**: このリポジトリの開発ログがそのまま素材になる。失敗も尺になる
- **難点**: 編集の巧拙が視聴維持率に直結

### 候補F: ビジュアル数学・物理
> 3Blue1Brown / manim 型

- **ポリシー耐性**: ◎
- **難点**: 競合が非常に強い。「高校数学の特定単元」「統計の誤解」などニッチを絞れば成立

## 2. 推奨

**候補A（シミュレーション検証）を軸に、候補C を看板シリーズとして併走**するのが最もバランスが良い。

理由:
1. 尺が自然に8〜12分に伸びる（可視化は時間を食う）
2. 生成物が全て一次データ・自作物 → 量産型判定を原理的に回避
3. Claude が企画から録画スクリプトまで一気通貫で担当できる
4. 1本ごとに「結論」が異なるため、テンプレ量産と判定されにくい

## 3. 技術パイプライン（この環境で完結する構成）

```
Claude が企画・台本を生成
  ↓
Claude が Canvas/SVG/WebGL の HTML、または Python(matplotlib/manim) を実装
  ↓
Playwright (Chromium は /opt/pw-browsers に導入済) で
  1920x1080 / 60fps のフレーム連番を出力
  ↓
ffmpeg で結合（8〜12分 = 約30,000〜43,000 フレーム）
  ↓
ナレーション音声を合成 or 自分で録音してミックス
  ↓
アップロード時に「合成コンテンツ」開示トグルを ON
```

- 尺の確保は「1本の動画 = 1つの問い」で構成し、条件を変えた再実行を3回入れると自然に8分を超える
- 長時間レンダリングは実時間録画ではなく **フレーム単位のオフスクリーンレンダリング** にすると安定する

## 4. 運用上の注意（収益化を守るため）

| 項目 | 方針 |
|---|---|
| 開示 | AI音声・AI生成映像を使うなら「変更または合成されたコンテンツ」トグルを必ず ON。これ自体では収益化資格を失わない |
| 投稿頻度 | 1日複数本の量産をしない。週1〜2本で、1本ずつ結論が違う状態を保つ |
| サムネ/タイトル | 同一テンプレの文字差し替えを避ける（量産判定の主要シグナル） |
| 概要欄 | データ出典と、使用したコードの GitHub リンクを置く。オリジナル性の証跡になる |
| ナレーション | 外部記事の逐語読み上げは絶対に避ける。必ず自分の観察・主張・驚きを混ぜる |
| 3ストライク | 警告 → 90日停止 → YPP 永久除外。警告が来たら量産型の構成を即刻やめる |
